汇总排查代理接入过程中最常遇到的报错和现象，按"症状 → 原因 → 解决"整理。更基础的问题先看 [FAQ](/docs/faq)。

## 404：模型名称不存在 / 分组下暂无可用渠道

**症状**：用 Codex 之类走 Responses API 的客户端接第三方中转站时，报类似「当前无法提供该模型：模型名称不存在，或您所在分组下暂无可用渠道」的 404。

**原因**：本地代理对请求做纯透传，不会自己生成这类报错——这是**上游供应商自己的网关**返回的。常见情况是客户端用的协议模式（如 OpenAI 较新的 Responses API `/v1/responses`）上游没有实现，只支持更早的 Chat Completions（`/v1/chat/completions`），上游网关找不到匹配的渠道就会报这种"听起来像模型问题、实际是端点问题"的错。

**解决**：在客户端（如 CC Switch）里把该供应商的协议格式从「responses 原生」切换成「Chat Completions」。这不是某一家供应商的个例——任何不支持 Responses API 的上游都会这样，跟代理本身无关。

## 请求发了，但总览页没有数据

排查顺序：

1. **`BASE_URL` 是否含 `/api/proxy/<供应商slug>` 前缀**——少了这个前缀，请求会 404，也不会落账
2. **代理是否在线**——桌面顶栏应显示「代理在线 · :17800」，显示离线的话检查应用是否在后台运行
3. **请求是否真的发出去了**——先用一条肯定会成功的真实请求测试，而不是直接怀疑统计有问题
4. **总览页的日期范围**——默认可能是"近 7 日"，更早的测试数据切不到对应范围会看不到

## 非 2xx 响应（如限流、鉴权失败）为什么没被记账

这是设计如此，不是 bug：**只有正常返回的调用才会落账**，429 限流、401/403 鉴权失败这类非 2xx 响应不会写入统计——避免这些错误请求污染你的用量数据。如果你的调用大量失败，问题出在上游（比如 API Key 或额度），而不是代理没记账。

## 成本显示「未配置定价」

该模型还没有在「设置 → 模型定价」里保存单价。去设置页把它的单价填上（可以先点「填入常见模型参考价」再按需修改），保存后旧记录和新记录都会按新单价重新计算显示。

## 自定义供应商保存失败

见[自定义供应商接入 → 保存失败怎么办](/docs/custom-provider)，常见原因是 slug 格式不对、跟内置供应商重名，或者地址不满足安全校验规则。

## 设了预算，但没收到通知

- **桌面端**：预算检查大约每 15 秒轮询一次，正常情况下超限后很快会有系统通知；先确认对应维度（全局/供应商/Agent/模型）确实产生了达标的用量
- **云平台**：走的是独立的后台批处理，**每 5 分钟**才处理一次，收到通知有延迟属正常现象，不是故障

详见[设置预算告警](/docs/alerts)。

## 悬浮卡片数据看起来没更新

悬浮卡片每 2.5 秒自动刷新一次；如果长时间没变化，先确认代理在线、且这段时间内确实有请求发生。卡片位置跑丢了可以在设置页点「重置位置」恢复。

## 多设备同步后数据对不上

同步基于事件唯一 ID 去重，正常情况下"冲突数"应该恒为 0。如果你观察到明显的数据缺失或重复，先确认两台设备用的是同一个账户登录，再检查同步时是否有网络错误提示；仍然异常的话，欢迎带上设备信息反馈给我们（见 [FAQ → 怎么反馈问题](/docs/faq)）。

## 安装被系统拦截（SmartScreen / 无法验证开发者）

不是病毒，是应用未购买代码签名证书导致的默认保护。详细处理步骤见[桌面应用 → 安装时遇到系统提示怎么办](/docs/desktop)。
