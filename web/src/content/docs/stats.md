统计页把每一次模型调用的 Token 与成本，按多个维度整理，方便看清"Token 花在哪"。想先了解每个页面长什么样，见[使用指南](/docs/usage)；这篇专注讲**怎么读懂这些数字**。

## 成本是怎么算出来的（实操例子）

Oxelia51 按模型精确计费，公式：

```text
成本 = prompt_tokens ÷ 1,000,000 × 该模型输入单价
     + completion_tokens ÷ 1,000,000 × 该模型输出单价
```

举个例子：假设 `deepseek-chat` 的单价是输入 $0.14 / 1M、输出 $0.28 / 1M（USD，每 1M tokens），一次请求消耗 `prompt_tokens=50000`、`completion_tokens=20000`：

```text
成本 = 50000 / 1,000,000 × 0.14 + 20000 / 1,000,000 × 0.28
     = 0.007 + 0.0056
     = $0.0126
```

几个关键点：

- **按模型名精确匹配单价**，供应商只决定转发给谁，跟计费无关（同一个供应商下不同模型价格可以完全不同）
- 单价来自「设置 → 模型定价」里你自己保存的值；**没配置的模型成本按 0 计，界面显示「未配置定价」**，不会用参考价瞎凑
- 「模型价格参考表」只是选型时看的市场参考价，**不会自动套用到你的成本计算**——要让某个模型真正参与计费，得先在「模型定价」里保存它的单价

## 趋势图怎么看

总览页的「近 14 天用量趋势」是按天聚合的 Token 柱状图。几个读图技巧：

- 某天突然冒高 → 大概率是跑了批量任务或某个 Agent 密集调用，可以切到「Agent 页」按当天时间范围核对
- 连续几天是 0 → 检查代理是否在线、`BASE_URL` 有没有失效（比如系统重启后忘记重新 export 环境变量）
- 只看某个时间段异常 → 切换日期范围到「近 7 日」，排行会跟着联动，只统计该范围内的数据

## 为什么某个供应商 / 模型不在排行里

排行只展示**有真实用量**的条目：0-token 的内置路由占位不会出现在用量排行里（避免"用过的"和"没用过但内置支持的"混在一起，误导判断）。如果你确实用了某个供应商但排行没显示，先检查请求是否真的落账了（见下节）。

## 下钻操作

- **供应商页**点某一行 → 展开该供应商被哪些 Agent 使用、各模型的明细
- **Agent 页**点某一行 → 展开该 Agent 用了哪些供应商 × 模型
- 下钻明细里同样支持按日期范围筛选

## 币种切换

- 「模型价格参考表」和总览的成本展示都支持 **USD / CNY 一键切换**
- 人民币汇率**每日从欧央行基准更新**；离线或拉取失败时，回退到上次成功获取的汇率，再不行则用内置参考值兜底
- 汇率来源与更新日期标注在价格表下方，可以自行核对

## 为什么数据是空的

刚接入代理、还没有任何请求经过时，统计页为空属正常。请依次检查：

1. 环境变量是否正确指向代理地址（`BASE_URL` 必须含 `/api/proxy/<供应商slug>` 前缀）
2. 请求是否真的走了代理——顶栏「代理在线」不代表请求经过了它，得看你的模型工具配置是否生效
3. 时间范围是否覆盖了请求发生的时间（默认视图可能是"近 7 日"，更早的测试数据切不到对应范围会看不到）

> 排障时建议先用一条真实请求验证，再看仪表盘是否出现数据。更多故障排查见[常见错误排查](/docs/troubleshooting)。
