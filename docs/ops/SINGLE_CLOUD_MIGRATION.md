# 单云整合评估报告

> 日期：2026-08-06
> 状态：评估完成，未实施

## 一、当前双云架构

```
用户 AI 工具（公网）
      │
      ▼
┌────────────────────── 阿里云 47.108.202.199（2C2G 起）──────────────────────┐
│  Nginx（80/443，公网入口）                                                  │
│  ├─ / → SSH 隧道 → 腾讯云 Langfuse web:3000                                  │
│  ├─ /api/auth/login → Go 后端 :8080                                         │
│  ├─ /api/trpc|auth|project|public → SSH 隧道 → 腾讯云 web                    │
│  └─ /api/ → Go 后端 :8080                                                    │
│  Go 代理网关 :9090（公网，43 供应商代理（撰写时 30））                        │
│  Go 管理后台 :8080（SmartKB Postgres :5432、Redis :6379）                    │
└──────────────────────────────────────────────────────────────────────────┘
      │ SSH 隧道（token-tunnel.service）
      ▼
┌────────────────────── 腾讯云 118.25.138.177（4C4G）────────────────────────┐
│  Langfuse web :3000 + worker :3030                                          │
│  ClickHouse :8123/9000（Token 事件存储）                                     │
│  PostgreSQL :5434（Langfuse 业务）                                           │
│  Redis :6379 / MinIO :9090                                                  │
│  C++ 分析引擎（token-analytics，每 5 分钟）                                  │
└──────────────────────────────────────────────────────────────────────────┘
```

**关键依赖**：
- Nginx（阿里云）经 **SSH 隧道**（token-tunnel.service）访问腾讯云 web——隧道中断 = 全站 502（曾发生）
- 代理网关（阿里云）→ ClickHouse（腾讯云）**跨云写入**（明文 HTTP）
- Go 后端（阿里云）→ 腾讯云 web 的健康检查

## 二、整合方案对比

### 方案 A：全迁阿里云（推荐候选）
- **迁移内容**：Langfuse 全套（web/worker/CH/PG/Redis/MinIO）→ 阿里云 Docker；C++ 引擎 → 阿里云；Nginx 直连本机 3000
- **阿里云需扩容**：当前规格不足（需 4C8G+，与腾讯云同规格）
- **收益**：✅ 消除 SSH 隧道（最大故障点）✅ 跨云延迟消除 ✅ 单点管理 ✅ 成本（一台高配 vs 两台）
- **风险**：⚠️ 迁移期数据搬迁（ClickHouse 数据量）⚠️ 阿里云公网 IP 变更（Nginx/域名 A 记录）⚠️ 备案域名关联
- **工作量**：1-2 天（数据迁移 + 配置收敛 + 验证）

### 方案 B：全迁腾讯云
- 腾讯云 4C4G 已跑数据层，加 Nginx + Go 后端 + 网关（需扩内存，当前 3.7G 紧张）
- **收益**：数据层不动（CH/PG 原位），迁 Nginx/Go 轻量
- **风险**：⚠️ 腾讯云 4G 内存跑全部（web 2.5G + CH 1G + worker + Go + Nginx ≈ 超限）⚠️ 需升级 8G
- **工作量**：1 天（Nginx/Go 迁移 + 域名解析）

### 方案 C：保留双云，消除隧道（折中）
- **核心问题**：隧道是单点。改为阿里云 Nginx **直连腾讯云公网**（开放腾讯云 3000 给阿里云 IP 或 HTTPS 反代）
- 或：**腾讯云 Nginx 直接对外**（域名解析到腾讯云），阿里云仅留代理网关（公网访问）
- **收益**：✅ 不动数据 ✅ 消除隧道 ✅ 风险低
- **工作量**：半天

## 三、建议

**短期（低风险，建议先做）**：方案 C——域名解析切到腾讯云，腾讯云加 Nginx 对外；阿里云保留代理网关（AI 工具连它）。消除 SSH 隧道单点，无需迁移数据。

**中期（若要成本最优）**：方案 A——全部迁阿里云（升级 4C8G），停腾讯云。适合流量增长后单云承载。

**不建议**：方案 B（腾讯云内存瓶颈，需升级且无优势）。

## 四、决策条件

- 若当前阿里云公网带宽/性能够用 → 方案 A（彻底单云）
- 若想最小改动 → 方案 C（隧道消除，立即消除 502 根因）
- 需用户确认：云厂商续费预算、是否接受域名解析变更窗口
